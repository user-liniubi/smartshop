## 3. 收尾前的问题与修复

### 3.1 配送政策被识别为未知意图

首次评测输入：

```text
现货商品多久发货？
```

模型曾返回 `unknown`。现在增加确定性配送政策规则，命中发货、配送、运费、物流时直接进入售后政策检索。

### 3.2 产品使用问题被识别为保修或换货

首次评测输入：

```text
十四寸笔记本支持自己加内存吗？
```

模型曾返回 `warranty_question`。现在当问题包含内存、接口、续航、连接、清洁等使用词，且用户没有明确要求退换货或保修时，后端会把意图修正为产品使用政策。

中间一次回归发现：订单查询“订单 A10087 现在发货了吗”受到配送规则影响。现已限定确定性配送覆盖只在没有明确订单号时生效，避免覆盖订单查询。

### 3.3 意图 JSON 容错

模型偶尔会在 JSON 前后输出说明文本。解析器现在会先直接解析完整 JSON，失败后再提取最外层 JSON object，并继续经过 Pydantic 严格校验；仍然无法解析时才走确定性关键词降级。

### 3.4 工单状态重复表达

改造前，工单创建系统消息中已有工单号，模型历史能看到该消息，最终回答又追加一次工单状态。

现在采用单一表达：

- 工单创建、审批和取消由 `system` 消息展示。
- 模型历史过滤系统消息，不向回答模型暴露内部工单通知。
- AI 回答只解释订单、资格、政策和排查建议，不再追加第二份工单状态。

## 4. 真实三轮售后冒烟

实际链路：

```text
“耳机坏了，想退货”
→ action=ask_more_info
→ 自动关联当前账号唯一耳机订单 A10086
→ 只追问具体故障

“订单号 A10086”
→ action=ask_more_info
→ 继续保留订单和退货任务
→ 仍只追问具体故障

“左耳没有声音”
→ 订单工具查询成功
→ RAG 命中 4 个片段
→ 资格结果 eligible
→ 参考退款金额 899.00 CNY
→ 创建待审批工单 AS-7539EDFA2F58
```

消费者消息记录中只有一条工单系统通知：

```text
售后工单 AS-7539EDFA2F58 已创建，当前等待人工审批。
```

AI 回答中没有重复工单号。随后人工申请成功：

```text
handoff_source=user
handoff_status=pending
pending_queue_count=1
```

本次第三轮请求约 41.84 秒，其中 BGE 冷启动约 37.9 秒，模型回答约 1.8 秒。这是冷启动耗时，不代表评测集稳定态 P95。
